\section{Mechanized Validation}
\label{sec:evaluation}

This section reports a repository snapshot, not a runtime-performance
benchmark.  On 2026-08-04 the migrated tree contained 13,093 lines across 100
production Lean files and 3,681 lines across 13 Lean regression modules.
Infrastructure itself comprised 65 modules.  A source scan found 191
compile-time \decl{example}, \decl{theorem}, or \decl{lemma} declarations in
\decl{CryptoTest}.

The acceptance sequence checked the import DAG and then completed
\texttt{lake build Crypto} (1,803 jobs), \texttt{lake build CryptoTest} (3,228
jobs), and the default \texttt{lake build} (3,252 jobs), without warnings.  Static
audits found no \decl{sorry}, \decl{admit}, explicit \decl{axiom}, or
\decl{unsafe} in production or test sources, and \texttt{git diff --check}
reported no whitespace errors.  The three opaque operational-admission
relations are explicitly counted as trust-boundary interfaces; the repository
provides no global admission fact or generic constructor for host functions.
These counts describe the current local snapshot; they are expected to change
as the library evolves.

The CI workflow runs the import checker before Lean and explicitly names the
\decl{Crypto}, \decl{CryptoTest}, and default targets on GitHub Linux.  It also
generates API documentation separately from the source \decl{docs/} tree.
This guards the logical hierarchy and the build boundary, while the theorem
regressions guard semantic equalities and exact cost order.

\subsection{What the validation establishes}

The tests demonstrate that the interfaces are not merely specialized natural-
number wrappers: the noncommutative and multidimensional models elaborate and
their laws compose through the generic APIs.  They also exercise the exact
chronology that would be hidden by a commutative model, including query issue
cost followed by environment cost and FIFO kernel actions.  Finally, existing
cryptographic results compile against the cost-erased views, providing a
regression check that the complexity refactor did not silently alter their
probability semantics.

The builds do not establish adequacy with physical execution time, completeness
of any overapproximating path relation, or security of an uninstantiated UC
protocol.  Those boundaries are the subject of the next section.
