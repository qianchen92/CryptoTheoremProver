\section{Soundness Boundaries and Future Work}
\label{sec:boundaries}

The architecture makes several internal connections precise, but its claims
remain relative to explicitly supplied models and certificates.

\paragraph{Higher-order program boundaries.}
\decl{Program.Code} is higher-order.  Values passed to \decl{pure}, continuation
functions in \decl{bind}, and branch conditions are Lean terms, and their host
reduction cost is not charged.  All explicit primitive calls are measured, but
the language is not yet a first-order RAM or Turing-machine semantics that
prevents hidden computation.  Consequently neither a bounded higher-order
program nor a value-only map is automatically promoted across the PPT boundary.

\paragraph{Trusted annotations and observations.}
\decl{CostedAlgebra.exec} is the authoritative exact annotation inside the
formal model.  The library proves that annotations compose and that bounds hold
over their support; it does not prove that an annotation equals wall-clock CPU
time.  Likewise, \decl{NatMeasure} is an explicit monotone additive observation,
not an automatically derived cost-model adequacy theorem.

\paragraph{Operational PPT admission.}
\decl{PPTAdmissible}, \decl{PPTOracleAdmissible}, and
\decl{PPTAddressedITMAdmissible} are opaque predicates tying exact semantics to
the claimed runtimes.  The generic library provides no facts or constructors
that admit arbitrary Lean functions.  Security predicates quantify only
records carrying such witnesses, and oracle composition plus closed UC
execution retain separate admission obligations.  This is an explicit
soundness firewall, not yet a mechanized RAM-adequacy proof: concrete
admission facts belong to a future first-order code semantics or to a clearly
identified external trust base.

\paragraph{Worst-case paths only.}
\decl{RandCosted.CostBound} is a support-wise worst-case predicate.  The joint
value--cost PMF remains available, but no expected-cost or tail-bound theory is
currently built on it.  Parallel composition, communication rounds, encoded
message length, and empirical host runtime are also outside the present core.

\paragraph{Oracle overapproximation and exchange.}
\decl{PossibleExecution} intentionally forgets response support; only
interpreter support implies a possible execution.  Moreover, exact oracle
interpretation itself needs no commutativity, but a coarse separated bound for
interleaved caller and implementation work requires the explicit
\decl{CostExchange} hypothesis.  Repeated-cost monotonicity is also stored
explicitly because an arbitrary ordered additive monoid does not derive it from
the order on natural counts alone.

\paragraph{Interactive certificates and capabilities.}
Fuel is solely a finite-execution control.  The runner does not inspect a cost
or fuel certificate and never removes a path because a proof is absent.
\decl{FuelCertificate.noTimeout} and stability are semantic proofs supplied for
a concrete closed world.  Port and send-as capabilities are only as strong as
the concrete \decl{PortSchema} and routing policy.  UC security is therefore
relative to the fixed address family, schema, cost model, measure, role
wrappers, certificates, and operational admissions.  In particular,
\decl{PPTAddressedITMCertificate} admits each role's exact handlers, while
\decl{PPTExecutionCertificate} separately admits the exact closed runner.

Current contexts use role-preserving injective address endomaps over a fixed
global address and port-schema universe.  They are not yet fully heterogeneous
contexts translating arbitrary schemas.  The layered bridge installs actual
party, manager, boundary, and ideal-functionality components, but it does not
by itself prove security of a concrete layered MPC protocol.

\subsection{Next steps}

The most direct extensions are: (i) replace the higher-order program boundary
with a first-order typed syntax whose interpreter produces operational
admission; (ii) relate selected resource algebras to a concrete RAM or machine
semantics and discharge the current opaque boundary; (iii) add expected cost, tail bounds,
parallel resources, communication, and round measures; (iv) generalize context
transport across heterogeneous address and port schemas; (v) automate common
fuel and operational-simulation proofs; (vi) instantiate the UC stack with
concrete protocols and functionalities; and (vii) formalize the ElGamal
IND-CPA reduction from DDH.
